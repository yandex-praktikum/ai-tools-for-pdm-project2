# Спецификация дашборда CertiGo

Соберите локальный дашборд из четырёх блоков. Страница может быть создана любым удобным инструментом. Источник каждого блока — проверенный SQL-результат, сохранённый в JSON в `dashboard/exports/`. Точный формат файлов приведён в `exports/README.md`. После заполнения скопируйте те же файлы в `../submission/exports/`.

## Блоки

| # | Блок | Экспорт | Источник | Тип |
|---|---|---|---|---|
| 1 | Воронка регистрация → оплата (5 этапов) | `exports/funnel.json` | запрос `funnel` | столбчатая |
| 2 | A/B `onboarding_v2`: основная метрика и guardrail | `exports/ab_onboarding.json` | запросы `ab_primary`, `ab_guardrail` | сгруппированные столбцы |
| 3 | Юнит-экономика платных каналов: CAC vs ARPU, ROMI | `exports/economics.json` | запрос `economics` | сгруппированные столбцы + подпись |
| 4 | Выручка по неделям (`succeeded`) | `exports/revenue_weekly.json` | отдельный проверенный query | линия |

## Требования к каждому блоку

* Значение берётся из проверенного SQL-результата, а не вводится вручную.
* Подпись называет метрику, период и знаменатель, если он применим.
* В подписи указан источник: имя экспорта и имя запроса.
* Пустое состояние: если файл экспорта отсутствует или повреждён, блок показывает «Нет данных: <имя файла>», а не ошибку скрипта и не выдуманные значения.

## Smoke-проверка

1. Дашборд открывается локально без ошибок в консоли браузера.
2. Каждый из четырёх блоков показывает данные из своего экспорта.
3. Значения каждого блока совпадают с результатом соответствующего SQL-запроса.
4. При временном удалении одного экспорта соответствующий блок показывает пустое состояние, остальные блоки не ломаются.
