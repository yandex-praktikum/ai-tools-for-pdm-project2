# Аналитический пакет CertiGo

Локальная рабочая среда для подготовки продуктового решения по зафиксированному срезу данных CertiGo. В комплекте есть схема и данные PostgreSQL, бизнес-контекст, правила расчёта, контракты результатов и локальная проверка.

## Результат работы

Подготовьте один связный пакет:

* пять читающих SQL-запросов в `submission/`;
* четыре JSON-экспорта для локального дашборда;
* `notes.md` с рамкой анализа;
* `release-decision.md` с решением, доказательствами, ограничениями и планом следующей проверки.

Имена и расположение файлов фиксированы. Полный контракт каждого результата описан в `submission/README.md`, а JSON — в `dashboard/exports/README.md`.

## Быстрый маршрут

1. Прочитайте `manager-brief.md`, `data-rules.md` и `ab-brief.md`.
2. Создайте локальную базу `certigo`, выполните `schema.sql`, затем `seed.sql`.
3. Проверьте загрузку по `CONTROL.md`.
4. Сохраните SQL-запросы и документы в `submission/`.
5. Сформируйте JSON в `dashboard/exports/` и скопируйте те же файлы в `submission/exports/`.
6. Настройте `check.config.json` и запустите проверку.

## Состав комплекта

| Файл или папка | Назначение |
|---|---|
| `manager-brief.md` | контекст и вопрос руководителя |
| `schema.sql`, `seed.sql`, `reset.sql` | создание, загрузка и повторная очистка базы |
| `data-rules.md` | словарь данных и правила расчёта метрик |
| `CONTROL.md` | проверка корректной загрузки базы |
| `ab-brief.md` | гипотеза, метрики и правило решения для `onboarding_v2` |
| `dashboard/SPEC.md` | требования к четырём блокам дашборда |
| `dashboard/exports/README.md` | JSON-контракты экспортов |
| `submission/` | результаты анализа |
| `check.mjs` | локальная проверка |
| `check.config.example.json` | пример строки подключения к PostgreSQL |

## Требования

Нужны Node.js 22+, PostgreSQL 16 и пользователь PostgreSQL с правом создавать и удалять базы. Для работы с базой подойдёт pgAdmin 4 или `psql`.

Проверка создаёт и удаляет временную базу `certigo_check_tmp` на сервере из конфигурации. Используйте локальный или изолированный сервер, а не рабочую production-базу.

## Подготовка базы

1. Запустите PostgreSQL и создайте базу `certigo` в UTF-8.
2. В Query Tool или `psql` выполните целиком `schema.sql`, затем `seed.sql`.
3. Выполните блок из `CONTROL.md`. Шесть количеств должны совпасть.
4. После загрузки выполняйте только читающие SQL-запросы.

Если загрузка прошла с ошибкой, выполните `reset.sql`, затем повторно `seed.sql`.

## Настройка и запуск проверки

Сначала создайте локальный конфигурационный файл и впишите доступ к PostgreSQL.

Windows PowerShell:

```powershell
Copy-Item check.config.example.json check.config.json
npm install
node check.mjs
```

macOS или Linux:

```bash
cp check.config.example.json check.config.json
npm install
node check.mjs
```

В `check.config.json` укажите `connectionString` для существующей базы, обычно `postgres`. Файл содержит доступ к вашему серверу и исключён из Git.

Проверка выводит состояние и баллы каждого раздела, затем общий результат из 100. Зачёт — от 60 баллов. Код `0` означает зачёт; код `1` означает незачёт или ошибку среды запуска. Контрольные значения и готовые запросы в вывод не попадают.
