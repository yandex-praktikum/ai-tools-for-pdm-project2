# Результаты анализа

Все необходимые файлы уже созданы в этой папке. SQL- и JSON-файлы намеренно пусты: заполните их, не меняя имена и расположение.

## Контракт файлов

| Файл | Что подготовить |
|---|---|
| `channels.sql` | один читающий запрос: новые пользователи по каналам за весь период |
| `funnel.sql` | один читающий запрос: пять этапов воронки и конверсии |
| `ab_primary.sql` | один читающий запрос: основная метрика `onboarding_v2` по вариантам |
| `ab_guardrail.sql` | один читающий запрос: оплаты `onboarding_v2` по вариантам |
| `economics.sql` | один читающий запрос: CAC, ARPU и ROMI по платным каналам |
| `notes.md` | рамка вопроса и границы анализа |
| `exports/funnel.json` | копия экспорта блока воронки |
| `exports/ab_onboarding.json` | копия экспорта блока A/B-теста |
| `exports/economics.json` | копия экспорта блока юнит-экономики |
| `exports/revenue_weekly.json` | копия экспорта выручки по неделям |
| `release-decision.md` | итоговое решение |

## SQL

В каждом SQL-файле должен быть один читающий запрос: `SELECT` или читающий `WITH`. Используйте только таблицы и определения из комплекта. Сначала выполните запрос на своей базе и проверьте его смысл, затем сохраните в нужный файл.

## Документы

### notes.md

Создайте связный документ, в котором явно зафиксированы:

* вопрос, на который принимается решение;
* критерий и применимые пороги;
* период данных;
* сегмент анализа;
* ограничения;
* путь от каждого ключевого факта к источнику из комплекта.

### release-decision.md

В первой непустой строке укажите один статус: `status: rollout`, `status: hold` или `status: rework`. Затем самостоятельно добавьте разделы:

* область решения;
* доказательства и таблицу «утверждение → query / источник»;
* решение по эксперименту;
* решение по бюджету каналов;
* ограничения;
* следующую проверку с метрикой, порогом и датой пересмотра;
* след работы с ИИ: что было поручено, что проверено и что исправлено.

Финальная формулировка должна опираться на проверенные данные и источники.

## JSON-экспорты

Сначала заполните файлы в `../dashboard/exports/` по инструкции `../dashboard/exports/README.md`. Затем скопируйте те же файлы в `submission/exports/`. Оба набора должны совпадать.

## Запуск проверки

Из корневой папки `certigo-project`:

```bash
npm install
node check.mjs
```

Если `check.config.json` ещё не создан, сначала скопируйте `check.config.example.json`. Параметры подключения описаны в корневом `README.md`.

Максимум — 100 баллов; зачёт начинается с 60. Проверка всегда выводит баллы и причину по каждому разделу, который не прошёл.
